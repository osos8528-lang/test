# 실습 검증 기록

측정일: 2026-10-07. Windows / Python 3.14.5 / SQLite / 로컬 단일 Uvicorn 프로세스.

## 자동 검사

- pytest 33개 통과: CRUD, 재조회, 검색, 입력 오류, 관리자 권한, 토큰 만료,
  비밀번호 해시, 동시 쓰기, WAL, Windows 부하 도구 종료를 검사했습니다.
- main.py 줄 커버리지 100%: 215개 실행 대상 줄, 누락 0줄. 모든 분기·입력 조합의 증명은 아닙니다.
- check_harness.py 3단계 통과: 보안 문자열 패턴, pytest, 집합 조회 예제와 WAL 설정 문자열 검사입니다.
- Windows 부하 도구의 실패 경로에서 DB 연결 누수로 파일 삭제가 실패하여 finally에서 연결을 닫도록 수정했습니다.

## 별도 DB 비교

각 100회, 동시 작업자 20개. 사용자 실습 DB와 분리했습니다.

| 설정 | 성공 | 실패 | 초당 시도 수 | DB 작업 p99 |
|---|---:|---:|---:|---:|
| DELETE 저널, 0.08초 대기, EXCLUSIVE 트랜잭션, 2ms 추가 지연 | 62 | 38 | 95.7 | 382.20ms |
| WAL, 5초 대기, 추가 지연 없음 | 100 | 0 | 119.5 | 729.76ms |

여러 조건이 달라 WAL만의 개선 효과가 아닙니다. 실패까지 포함한 처리 시간이며 HTTP 가용성도 아닙니다.
교재의 99.99% SLA/서브밀리초 문구를 그대로 사용하지 않았습니다.

## 실제 HTTP API 부하

별도 로컬 서버와 새 DB에서 POST /todos를 1,000회, 동시 작업자 20개로 실행했습니다.

- 소요 6.20초, HTTP 201 1,000건, 관측 실패 0건.
- 처리량 161.4건/초.
- p50 70.52ms, p95 272.08ms, p99 1,107.84ms.
- API p99 100ms 목표 미달. 긴 대기시간 원인은 별도 프로파일링이 필요합니다.
- 단일 PC의 짧은 실험입니다. 장기 가용성, 인터넷 환경, 모든 API 성능을 보장하지 않습니다.
